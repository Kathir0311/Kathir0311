      Add sample files

      A sample is a finished, correctly tagged PDF the way the client wants it (their own tagged file, or one you approved). The tool reads every tag — what kind of text gets which tag, the wording, the running heads and feet, which tag holds which — and stores it. When it converts a file of that client it uses this for every tag it is not sure of. No client chosen: the samples are common — used for every client.

      How the samples are used

      • Tags the tool doubts (a heading found by size, a short bold line, a caption, a note) take the tag the most similar sample text has — when the samples agree.
      • Wording the client's samples always tag one way (“Key messages” → H2, “Abstract” → H1) is tagged the same.
      • Running heads and feet the samples print become artifacts.
      • Heading levels never jump; hand edits are never touched; every change carries a note samples: … in the editor.
      • In the editor, the properties of a tag show what the samples say about it — one click takes their tag.
      • Files approved in Files can be added as samples too (Add to samples) — the more good files, the better the next ones.
      • A profile uses the samples of the client with its name (or the one in its Samples client option) plus the common ones; switch it off with Learn from sample files.

      Learning curve

      first-pass quality of approved files model accuracy (held-out)

      First-pass quality: the share of text tags the tool got right before anybody changed them. Model accuracy: measured on sample files the model was not trained on.

      Whom the brain trusts

      Every approved file shows which source was right. A source that is often right counts more next time — the brain's own decisions get better by themselves.

      Brain settings

      ✂ Zones — where a paragraph starts, learned from people

      Every time the tool decides whether two lines are one paragraph (one zone) it writes the pair down. When a person cuts a zone in two, or joins two, that is a correction; the corrections of a client (and of every client, once two agree) teach a small model that moves the tool's own rule — only where the evidence is, and only after it has been right on pages and files it was not trained on. What people do is learned a few seconds after the edit, in a process of its own.

      ✍ Learned code — rules the learning engine wrote itself

      From the fixes people make, the engine finds the pattern (“set in this font, this size, bold → H3”) and writes it as a small Python rule. Each rule is checked against a whitelist before it may run, tested on every finished tag in the database, and only becomes active when it is right ≥ 93 % of the time. A rule people keep undoing is retired by itself.
